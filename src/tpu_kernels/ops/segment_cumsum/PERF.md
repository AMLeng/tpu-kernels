# Segment cumsum

Target: ≥80% HBM BW @ (M=2^28, mean_length=1024), bf16
Current: 26.3% HBM BW @ bm=262144 (M=2^28, mean_length=1024)
Bottleneck: VPU throughput in the within-row seg-HS. Each level still runs cmpi + select + addf on (T, 128) bf16; the lane shift is now MXU-issued (off VPU critical path) and the sid roll runs in parallel with the matmul. Sweep monotonic up to bm=262144 (14.0% → 26.3%) then dips at bm=524288 (25.5%) — the MXU/VPU balance favors smaller tiles. Default pallas_call already pipelines DMA (verified earlier with emit_pipeline as no-op). 1M block still OOMs scoped VMEM (16.04 MiB > 16 MiB).
Next: 80% target is structurally out of reach for VPU-only segmented prefix on v5e — per-element VPU op count (~30 with the MXU shift) exceeds the bytes/element budget at HBM peak. Path forward is an MXU-prefix design where the per-row cumsum itself comes from a triu matmul (as in cumsum, which hits 80%) and segment boundaries apply a localized correction on the small subset of boundary positions, not on the full (T, 128). Previous PFB attempt landed at <10% BW because the correction operated on (T, 128); the goal here is to keep correction cost proportional to boundary count, not row count.
